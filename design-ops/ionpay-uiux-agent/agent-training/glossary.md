# ionPAY UI/UX Agent Glossary

## Design-only

A visual, Figma, token, prototype or component artifact that helps define the product experience but is not production app code.

## Backend truth

The backend-confirmed state that determines whether money movement, balances, receipts or payment completion are real.

## False success

A dangerous UI state where the interface implies that a payment, transfer, receipt or balance update is complete before backend truth confirms it.

## Proof state

A UI state that communicates evidence such as trace ID, receipt status, timestamp, counterparty or backend confirmation.

## Module

A product area such as Home, Pagar, Cobrar QR, Activity, Receipt Center, Merchant, Security or Profile.

## Device matrix

The set of screen variants across small phone, standard phone, large phone, tablet portrait and tablet landscape.

## Implementation bridge

The controlled route from design artifact to app code, passing through orchestration, scope, engineering, financial safety, frontend review and founder approval.

## Agent observe mode

A state where another agent may read the UI/UX operation center but may not modify visual direction, packs, tokens or prototypes.

## Terminal proof layer

The `#ascii` or dark technical layer used for receipts, traceability and verification states. It is secondary, not the primary daily wallet style.

## V1 hidden feature

A feature that may exist in future or internal planning but must not be exposed publicly in V1, such as public USDT surface or enabled conversion unless explicitly approved.
